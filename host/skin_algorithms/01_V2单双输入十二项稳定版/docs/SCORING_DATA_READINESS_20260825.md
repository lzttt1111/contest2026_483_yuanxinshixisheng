# AISIA V2本地评分数据准备度与最终输出合同

## 结论

当前单RGB十二项结果已经能够支持后续使用数万张本地图片建立医生V2评分系统：

- 医生11份V2需求已锁定为11个正式模块；
- 137个核心评分输入均有稳定ID、单位、方向、来源检测器和显式代理公式；
- 当前clinic28-25单RGB实测为11/11模块完整、137/137输入可用；
- 三维深度、体积或位移类需求均明确保存为2D/2.5D工程代理，不宣称物理3D；
- 单RGB与四光源共用`production_proxy_v1`及同一137项公式；
- 参考人群分布、年龄/肤质分层及最终等级边界主要使用数万张单RGB结果拟合；四光源仅做同评分空间的映射与一致性验证，不建立第二套评分。

当前仍未完成的是人群标定，而不是指标采集。后续需用医学专家评分、参考人群分位数和重复拍摄数据重新拟合锚点与等级边界。

## 1000张新旧评分桥接方案

本阶段不重跑旧几万张。先抽取约1000张具有代表性的单RGB图片，用当前算法重新检测，并把同一样本的旧九项评分输入/旧分数与新137项输入配对：

1. 旧九项分别拟合单调映射，优先采用分位数映射或保序回归，目标是让新算法分数重新落回旧几万人群分布，降低算法升级产生的评分漂移；
2. 按年龄、肤质、性别、图像质量等现有可用分层检查映射残差，禁止只校正总体均值；
3. 映射前后保存P10/P25/P50/P75/P90、均值、标准差、等级迁移矩阵和异常样本清单；
4. 新增模块和旧系统没有的指标，使用这1000张建立首版分位数锚点，版本标记为`bootstrap_1000_v1`；
5. 所有映射只作用于评分层，不回写检测器原始JSON、Mask、数量或面积；
6. 将来重跑新几万张后发布新标定版本，旧的1000张映射版本保留用于回溯和灰度回滚。

scoring JSONL同时保存旧`scoring_features`和新`v2_scoring_features`，可直接按输入签名配对，不需要保留1000张样本的Word和检测图片。

## 数万张评分模式

正式批量标定使用`run.py --output-profile scoring`。每张图片只保存一行JSONL，不保存检测图、CSV或Word，并包含：

- 输入签名与`capture_profile`；
- 12项成功状态、图像质量、各服务耗时；
- 旧九项兼容`scoring_features`；
- 新增11模块`v2_scoring_features`，合计137项；
- `v2_scoring_results`及统一评分版本；
- `v2_scoring_completeness`，用于剔除证据不完整样本。

这套JSONL足以计算单RGB人群分布、分区分位数、模块锚点和最终0～100分映射，不需要保留每张图片的Word和结果图。

## 评分边界

- 当前分数仍属于工程代理分，不代表已经完成医学人群标定；
- 0～100方向统一为数值越高、图像问题负担越明显；
- 零目标的计数/面积/长度保留真实0，P50/P90等无样本分布值标记不可评估；
- 质量REJECT、遮挡严重和证据不完整样本不得进入人群锚点拟合；
- 单RGB与四光源使用相同公式版本，但不同成像路线必须在数据中保留Profile，便于后续映射审计。
