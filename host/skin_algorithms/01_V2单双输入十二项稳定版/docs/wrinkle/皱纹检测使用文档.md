# 皱纹检测使用文档

## 1. 文档说明

本项目用于对**单张正脸照片**进行皱纹检测，输出皱纹候选图、最终皱纹叠加图、人脸医美分区图、分区量化 CSV 以及完整运行摘要 JSON。

项目支持两种使用方式：

1. **本地单图测试**：直接读取 WSL 中的本地图片，结果保存在项目的 `output/` 目录。
2. **Celery Worker 服务**：后端通过 Celery 传入 OSS 图片 key，Worker 下载图片、执行检测，再将结果上传回 OSS。

> 说明：检测结果属于图像算法分析结果，不应单独作为医疗诊断、治疗指征或疗效承诺依据。

## 第一部分：输入是什么

### 3. 本地单图输入

本地入口的命令格式为：

```bash
python main.py <图片路径> [运行预设]
```

例如：

```bash
python main.py data/test_images/1000058_1.jpg fast
```

输入由两部分组成：

| 输入 | 是否必填 | 含义 |
|---|---|---|
| `<图片路径>` | 是 | WSL/Linux 中可读取的单张人脸图片路径，可以是相对路径或绝对路径 |
| `[运行预设]` | 否 | `fast`、`balanced` 或 `full`；不传时使用 `.env` 中的 `WRINKLE_RUN_PRESET`，默认是 `balanced` |

建议使用 JPG 或 PNG 图片。Worker 会识别的扩展名包括：`.jpg`、`.jpeg`、`.png`、`.bmp`、`.webp`、`.tif`、`.tiff`。

对输入照片的建议：

- 一张图片只包含一张主要人脸；算法只处理检测到的主要人脸。
- 使用清晰、正面的全脸照片，尽量避免侧脸、严重遮挡、明显运动模糊和过暗画面。
- 额头、眼周、鼻唇沟和嘴角附近尽量完整可见。
- 不要求提前裁成正方形。程序会自动检测人脸、裁剪、居中，并生成 `1024 × 1024` 的标准化分析图。
- 如果 MediaPipe 无法检测到人脸关键点，程序会失败退出，不会退回整张图片直接检测，以免把背景纹理误判为皱纹。

### 4. Celery Worker 输入

线上 Worker 的队列名默认是：

```text
wrinkle-detection-worker
```

任务名默认是：

```text
wrinkle-detection-worker.analyze_image
```

队列名和任务名前缀实际都取自 `.env` 的 `SERVICE_NAME`。

Celery 任务参数如下：

| 参数 | 类型 | 是否必填 | 含义 |
|---|---|---|---|
| `task_id` | `str` | 是 | 任务标识，同时作为结果 OSS 路径的一部分 |
| `oss_key` | `str` | 是 | 输入图片在配置的 OSS Bucket 中的对象 key，不是本地文件路径 |
| `oss_result_prefix` | `str \| None` | 否 | 输出文件的 OSS 前缀；为空时使用 `.env` 中的 `OSS_RESULT_PREFIX`，仍为空则默认 `{SERVICE_NAME}/v1/` |
| `algorithms` | `list[str] \| None` | 否 | 可传 `wrinkle_detection` 或 `wrinkle`；也可附带一个 `fast`、`balanced`、`full` 运行预设 |

任务输入示意：

```json
{
  "task_id": "abc123",
  "oss_key": "input/face/abc123.jpg",
  "oss_result_prefix": "wrinkle-results/v1/",
  "algorithms": ["wrinkle_detection", "balanced"]
}
```

Worker 会先把 OSS 图片下载到任务独享的临时目录，再把本地临时文件交给同一个 Pipeline 处理。

### 5. 运行所需的非图片输入

除图片外，运行还依赖以下内容：

- 固定 CPython `3.10.12`、uv `0.11.27` 和已提交的 `uv.lock`。
- `models/best.pt`、`models/face_landmarker.task`、`models/selfie_multiclass.tflite` 三个模型文件。
- `pyproject.toml` 中声明的 Python 依赖。
- Linux 图像运行库，以及用于中文卡片渲染的 `fonts-noto-cjk` 字体。
- Worker 模式还需要可连接的 Redis、阿里云 OSS Bucket 和有效凭证。

## 第二部分：项目如何运行、输出文件代表什么

## 6. 在当前 WSL 中运行本地单图检测

### 6.1 进入项目目录

```bash
cd /opt/dermavision
```

### 6.2 使用现有虚拟环境

项目当前已经存在 `.venv/`，可以直接激活：

```bash
source .venv/bin/activate
python --version
```

如果需要重新安装或同步依赖，可使用项目当前已安装的 `uv`：

```bash
uv sync --frozen --managed-python --python 3.10.20
```

Ubuntu 24.04 x86_64 服务器首次部署直接执行完整安装与自检：

```bash
bash scripts/bootstrap_uv.sh
```

若系统依赖尚未安装，可执行：

```bash
sudo apt-get update
sudo apt-get install -y \
  ffmpeg fonts-noto-cjk \
  libegl1 libgles2 libgl1 libglib2.0-0 libgomp1 \
  libsm6 libxext6 libxrender1
```

### 6.3 执行检测

快速预览：

```bash
python main.py data/test_images/1000058_1.jpg fast
```

日常推荐：

```bash
python main.py data/test_images/1000058_1.jpg balanced
```

最大召回：

```bash
python main.py data/test_images/1000058_1.jpg full
```

也可以不激活虚拟环境，直接执行：

```bash
uv run python main.py data/test_images/1000058_1.jpg balanced
```

三个预设的区别：

| 预设 | 特点 | 适用场景 |
|---|---|---|
| `fast` | 推理组合最少、速度最快 | 联调、快速预览 |
| `balanced` | 速度与召回率折中，项目默认值 | 日常检测、正式展示 |
| `full` | 尺度、增强和翻转组合最多，耗时最长 | 需要尽量提高召回率的离线分析 |

当前示例图片在本机 CPU 环境中，已有结果记录为：`fast` 约 14 次推理，`balanced` 约 84 次推理。耗时会随 CPU、并发量、图片和依赖版本变化，不应把示例耗时当作固定 SLA。

运行过程中会打印各次推理和阶段状态。成功后，终端最后会打印 `Pipeline` 返回字典，其中：

- `status`：`success` 或 `failed`。
- `results`：已生成结果文件的本地绝对路径。
- `metadata`：运行预设、设备、耗时、成功/失败推理次数和完整 `summary`。

### 6.4 本地输出目录命名

每次运行会新建独立目录，不会覆盖上一轮结果：

```text
output/{输入图片文件名}_{运行预设}_{YYYYMMDD_HHMMSS}_{进程ID}/
```

例如：

```text
output/1000058_1_fast_20260709_175217_849853/
```

## 7. 启动 Celery Worker

### 7.1 准备配置

```bash
cd /opt/dermavision
cp .env.example .env
```

至少确认以下配置已填写为真实可用值：

```env
SERVICE_NAME=wrinkle-detection-worker
CELERY_BROKER_URL=redis://127.0.0.1:6379/0
CELERY_RESULT_BACKEND=redis://127.0.0.1:6379/1
OSS_ACCESS_KEY_ID=...
OSS_ACCESS_KEY_SECRET=...
OSS_ENDPOINT=https://oss-cn-hangzhou.aliyuncs.com
OSS_BUCKET_NAME=...

WRINKLE_RUN_PRESET=balanced
WRINKLE_CPU_THREADS=6
WRINKLE_DEVICE=auto
WRINKLE_OUTPUT_DIR=output
```

`.env` 含敏感凭证，已经被 `.gitignore` 忽略，不要提交到仓库。

### 7.2 直接启动 Worker

```bash
source .venv/bin/activate
celery -A src.worker worker \
  --loglevel=info \
  --queues=wrinkle-detection-worker
```

如果修改了 `SERVICE_NAME`，`--queues` 后的队列名必须使用相同值。

### 7.3 使用 Docker Compose 启动

```bash
docker compose up -d --build
docker compose logs -f worker
```

当前 `docker-compose.yml` 使用 `network_mode: host`，让容器连接宿主机上的 Redis；同时把本地 `data/` 和 `models/` 挂载到容器中。

### 7.4 Worker 成功返回

Worker 会把 Pipeline 映射出的结果上传到：

```text
{结果前缀}{task_id}/{结果key}.{原扩展名}
```

返回示意：

```json
{
  "record_id": "abc123",
  "status": "success",
  "raw_result": {
    "stage2_overlay": "wrinkle-results/v1/abc123/08_最终皱纹检测图.jpg",
    "region_tiles": "wrinkle-results/v1/abc123/24_皱纹分区汇总图.jpg",
    "region_metrics_csv": "wrinkle-results/v1/abc123/region_metrics_csv.csv",
    "summary_json": "wrinkle-results/v1/abc123/summary_json.json"
  },
  "metadata": {
    "algorithm": "wrinkle_detection",
    "run_preset": "balanced",
    "device": "cpu",
    "successful_runs": 84,
    "failed_runs": 0,
    "region_analysis_status": "ok"
  }
}
```

`raw_result` 的值是 OSS key，不是本地路径，也不是可直接公开访问的 URL。是否可通过 URL 访问取决于 Bucket 权限及后端的签名方式。

## 8. 输出文件总览

一次正常的本地运行会生成以下 13 个主要文件：

| 文件名 | Pipeline / OSS 结果 key | 主要含义 | 推荐用途 |
|---|---|---|---|
| `00_标准化人脸分析图.png` | 不上传 | 黑底、居中、标准化为 `1024 × 1024` 的算法分析图 | 算法调试、确认裁脸和皮肤 mask |
| `00_标准化人脸展示图.png` | `preprocessed_face` | 保留展示背景的标准化人脸图 | 展示检测所使用的人脸范围 |
| `01_第一阶段候选皱纹图.jpg` | `stage1_candidates` | 第一阶段高召回皱纹候选线叠加图，尚未完成严格人脸区域过滤 | 算法召回检查，不建议作为最终结果 |
| `06_皱纹投票热力图.jpg` | `vote_heatmap` | 多视图、多增强、多尺度推理的重复投票热力图 | 观察候选线在多次推理中的一致性 |
| `08_最终皱纹检测图.jpg` | `stage2_overlay` | 人脸规则后处理后的最终皱纹线叠加图 | **最主要的皱纹检测展示图** |
| `09_最终皱纹中心线.png` | `stage2_centerline` | 最终皱纹中心线二值 mask，白色是皱纹线、黑色是背景 | 后续程序处理、长度和区域统计 |
| `12_人脸区域过滤调试图.jpg` | `face_filter_debug` | 允许区和眉毛、眼睛、鼻子、嘴唇等禁用区的彩色调试图 | 排查过滤边界和误检原因 |
| `20_皮肤纹理参考图.png` | `texture_reference` | 有效皮肤区域的高斯高通 + CLAHE 灰度纹理参考图 | 纹理观察和未来模型研究；当前不会用它硬过滤结果 |
| `21_皱纹检测阶段对比图.jpg` | `comparison` | 左：标准化展示图；中：阶段 1 候选；右：阶段 2 最终结果 | 直观比较后处理前后的变化 |
| `23_全脸皱纹分区结果图.jpg` | `region_overlay` | 最终皱纹按医美区域分配后的全脸分区图，显示区域轮廓、皱纹线、简称和相对分数 | 全脸分区结果展示 |
| `24_皱纹分区汇总图.jpg` | `region_tiles` | 按相对分数排序的 Top 分区卡片，最多 10 个、两列排列，保留文字指标 | 内部排错/报告 |
| `25_region_metrics.csv` | `region_metrics_csv` | 每个检测到皱纹的区域对应一行量化指标 | 数据分析、Excel 查看、结果入库 |
| `summary.json` | `summary_json` | 输入、预处理、模型、推理过程、阶段统计、分区指标和运行环境的完整摘要 | 程序验收、问题追踪、结果留档 |

补充说明：

- `06_皱纹投票热力图.jpg` 的颜色表示不同推理组合对同一位置的检出一致性。暖色通常表示投票比例更高，但它**不是临床严重度，也不是校准后的概率**。
- `08_最终皱纹检测图.jpg` 是正常业务展示时最应优先使用的结果。
- `09_最终皱纹中心线.png` 中的长度单位是标准化图上的像素，不是毫米。
- `24_皱纹分区汇总图.jpg` 卡片中的 `count` 是近似线段数，`len` 是该区域中心线像素总数。
- `00_标准化人脸分析图.png` 和 `00_标准化人脸展示图.png` 均会进入 Pipeline 的完整结果清单，并由 Worker 上传。

### 8.1 `12_人脸区域过滤调试图.jpg` 颜色含义

| 颜色 | 含义 |
|---|---|
| 绿色 | 允许输出皱纹的有效皮肤区域 |
| 红色 | 眉毛禁用区域 |
| 蓝色 | 鼻子禁用区域 |
| 紫色 | 胡须/人中及嘴唇禁用区域 |
| 青色 | 眼睛、睫毛、双眼皮统一禁用区域 |
| 黄色轮廓 | 完整额头允许区域边界 |

### 8.2 分区名称与简称

分区分析最多可出现以下区域。某个区域没有出现在 CSV、JSON 或卡片中，通常表示该区域没有分配到有效皱纹中心线，不代表程序失败。

| `region_key` | 中文名称 | 简称 |
|---|---|---|
| `forehead` | 额头纹 | `FH` |
| `glabella` | 眉间纹 | `GL` |
| `left_crow_feet` / `right_crow_feet` | 左/右鱼尾纹 | `LCF` / `RCF` |
| `left_under_eye` / `right_under_eye` | 左/右眼下细纹 | `LUE` / `RUE` |
| `left_nasolabial` / `right_nasolabial` | 左/右法令纹 | `LNL` / `RNL` |
| `left_marionette` / `right_marionette` | 左/右木偶纹 | `LM` / `RM` |
| `other` | 其他纹 | `OT` |

`其他纹` 表示已经检测到、但没有被分配到上述命名区域的剩余皱纹线。

## 9. `25_region_metrics.csv` 字段含义

CSV 使用带 BOM 的 UTF-8 编码，便于 Excel 正确显示中文。

| 字段 | 含义 |
|---|---|
| `region_key` | 程序使用的稳定区域英文 key |
| `region_name` | 中文区域名称 |
| `short_name` | 分区图和卡片图使用的英文简称 |
| `relative_score` | 同一张脸内部的区域相对分数，最高区域归一化为 100；只用于本图内部排序 |
| `segment_count` | 基于最终中心线连通域得到的近似皱纹条数；不是医学金标准 |
| `wrinkle_pixels` | 该区域所有皱纹中心线的像素总数，可理解为标准化图上的总线长近似值 |
| `mean_segment_length` | 该区域皱纹线段的平均长度，单位为标准化图像素 |
| `max_segment_length` | 该区域最长皱纹线段的长度，单位为标准化图像素 |
| `density_per_10k` | 每 10,000 个区域像素对应的皱纹中心线像素数，用于减小区域面积不同造成的影响 |
| `share_pct` | 该区域皱纹中心线像素占全脸最终皱纹中心线像素的百分比 |
| `area_px` | 该区域 mask 的面积，单位为标准化图像素 |

`relative_score` 的基础分数同时考虑了区域皱纹总长度、区域面积和近似条数，再按当前图片中最高分区域归一化。因此：

- 100 表示**这张图片中**得分最高的区域，不等于“100 分严重皱纹”。
- 它适合做单张脸内部的区域排序，不是医学分级。
- 不建议直接用它比较不同人的绝对严重程度；跨时间比较也应尽量保持拍摄距离、角度、光照和清晰度一致。

## 10. `summary.json` 主要字段含义

`summary.json` 信息较完整，可以按以下几组理解：

| 字段或字段组 | 含义 |
|---|---|
| `weights`、`source`、`output_dir` | 本次使用的模型、输入图片和输出目录路径 |
| `original_image_size` | 原始输入图片宽高 |
| `preprocessed_image_size` | 标准化分析图宽高，当前通常为 `1024 × 1024` |
| `preprocess_status`、`preprocess_crop_box`、`preprocess_scale` | 人脸裁剪、居中和缩放状态及参数 |
| `run_preset`、`estimated_runs`、`cpu_threads`、`device` | 本次运行预设、计划推理次数、CPU 线程数和实际设备 |
| `class_names` | 模型类别映射，当前为 `forehead`、`frown`、`wrinkle` |
| `successful_runs`、`failed_runs`、`total_instances` | 成功/失败推理次数和累计检出实例数 |
| `stage1_*` | 第一阶段高召回候选 mask、中心线和推荐候选的像素数及占比 |
| `stage2_*` | 人脸规则后处理后最终 mask、中心线和推荐结果的像素数及占比 |
| `face_filter_status`、`semantic_skin_status` | 人脸关键点和语义皮肤分割的执行状态 |
| `region_analysis_status` | 分区分析状态；正常应为 `ok` |
| `elapsed_seconds` | 算法主程序总耗时，单位为秒 |
| `runs` | 每一次推理的视图、增强方式、输入尺寸、翻转状态、实例数和耗时明细 |
| `region_metrics` | 与 CSV 对应的分区量化结果数组 |
| `ultralytics_version`、`torch_version`、`python_version`、`platform` | 运行环境版本，用于复现和排错 |

判断一次结果是否完整，建议至少检查：

```text
region_analysis_status == "ok"
successful_runs > 0
failed_runs == 0
```

并确认 `stage2_overlay`、`region_overlay`、`region_tiles`、`region_metrics_csv` 和 `summary_json` 均存在且可读取。

## 11. 其他可能出现的输出

### 11.1 `region_analysis_error.txt`

只有第三阶段分区分析发生异常时才会生成，内容是 Python 异常堆栈。此时第一、第二阶段图片可能已经生成，但 Pipeline 会因为 `region_analysis_status` 不是 `ok` 而把整次处理判定为失败。

### 11.2 `runs/` 目录

算法底层支持 `--save-runs` 保存每一次推理的中间结果，届时会产生 `runs/` 调试目录。正常通过 `main.py` 或 Worker 运行时，Pipeline 固定使用 `save_runs=False`，因此默认不会生成该目录。

### 11.3 `output/*.zip`

当前 `output/` 中已有一个示例：

```text
1000058_1_balanced_20260709_003124_1381433.zip
```

从当前 `main.py`、Pipeline、Worker 和算法主程序中未发现自动创建 ZIP 的逻辑，因此它应视为已有结果目录的额外归档副本。正常运行不会自动生成 ZIP；如需要压缩结果，需要另行执行打包操作。

## 12. 常见失败与排查

| 现象/退出码 | 含义与处理建议 |
|---|---|
| `exit code 2` | 输入图片、权重或必要模型文件不存在；检查图片路径和 `models/` 下三个模型 |
| `exit code 3` | YOLO 模型加载失败；检查 `best.pt`、依赖版本和 Worker 日志 |
| `exit code 4` | FaceLandmarker 未成功检测到人脸；检查是否为清晰正脸、是否严重遮挡、图片是否能正常解码，以及 MediaPipe 模型和系统库 |
| `exit code 5` | 人脸标准化预处理失败；结合终端或 Celery Worker 日志查看具体状态 |
| `region_analysis_status != "ok"` | 分区分析失败；查看输出目录中的 `region_analysis_error.txt` 和 `summary.json` |
| `24_皱纹分区汇总图.jpg` 中文显示为 `????` | 安装 `fonts-noto-cjk`；Dockerfile 已包含该字体依赖 |
| OpenCV / MediaPipe 导入失败 | 检查 `libegl1`、`libgles2`、`libgl1`、`libglib2.0-0` 等系统库是否安装 |
| 推理速度较慢 | 使用 `fast` 预设做联调；正式展示使用默认的 `balanced` |

本地失败时，`main.py` 会打印 `status: failed`、错误消息、返回码、输出目录和算法参数。Worker 失败时会返回 `error_message`，有诊断信息时还会包含 `error_details`。排错时应优先查看终端或 Celery Worker 日志，再结合输出目录和 `summary.json` 定位。
