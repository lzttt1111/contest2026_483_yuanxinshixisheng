# 皱纹检测前后端对接说明

## 1. 对接链路

手机端不直接调用 `pipeline.py` 或 `worker.py`。推荐链路如下：

```text
手机拍照 → 业务后端上传原图到私有 OSS → 后端投递 Celery 任务
        → 皱纹检测 Worker 下载并分析 → 全部产物上传 OSS
        → Worker 返回 OSS key → 后端生成临时签名 URL → 手机展示
```

- `src/pipeline.py`：运行算法，收集全部结果，并标记 `output-end/` 中的展示图。
- `src/worker.py`：接收 Celery 任务、下载原图、调用 Pipeline、上传全部结果并返回 OSS key。
- `src/core/config.py`：读取 Redis、OSS、服务名、超时等环境配置。
- `src/core/storage.py`：负责 OSS 下载和上传。

## 2. Celery 调用约定

- Queue：`wrinkle-detection-worker`（实际值由 `SERVICE_NAME` 决定）
- Task Name：`wrinkle-detection-worker.analyze_image`
- 默认算法模式：`balanced`

任务参数：

```json
{
  "task_id": "abc123",
  "oss_key": "user-upload/abc123.jpg",
  "oss_result_prefix": "wrinkle-results/v1/",
  "algorithms": ["wrinkle_detection", "balanced"]
}
```

其中 `task_id` 和 `oss_key` 必填；其他参数可省略。`oss_result_prefix` 无论是否带末尾 `/`，Worker 都会自动规范化。

## 3. 成功返回结构

返回结果同时包含 `raw_result` 和 `display_result`：

- `raw_result`：本次运行产生的全部文件，包括排错图、CSV、JSON、20/23/24 号图和每张分区图。现阶段后端一次性接收并保存这一完整对象。
- `display_result`：只是对 `raw_result` 中“当前计划给用户展示的图片”再做一层结构化标记，不会减少或替代 `raw_result`。
- `metadata`：运行模式、耗时、成功/失败推理次数及分析摘要。

实际 `raw_result` 还会包含其余全部根目录产物。分区图根据本次检测结果动态返回：只有实际检出且生成卡片的分区才出现。每张分区图会同时：

1. 以 `region_<英文分区名>` 的平铺字符串出现在 `raw_result`；
2. 以带完整量化指标的对象出现在 `display_result.regions`。

`display_result.regions` 按 `relative_score` 从高到低排列。前端使用 `region_name` 展示中文名称，使用 `image_oss_key` 加载对应的 `360×240` 纯图片；量化字段继续保留在 JSON 中但不绘制到图片。后续若新增用户展示图片，只需扩展展示清单，不需要改变“全部文件均在 `raw_result` 返回”的原则。

## 4. OSS 路径与权限

- 所有文件都会上传 OSS。
- 根目录图片使用：`{prefix}{task_id}/中文图片名`；英文 `raw_result` key 保持不变。
- CSV/JSON继续沿用：`{prefix}{task_id}/{raw_result_key}.{扩展名}`。
- 用户展示图使用：`{prefix}{task_id}/output-end/中文图片名`。
- OSS Bucket 保持私有。Worker 只返回 OSS key，不返回公开 URL，也不持有手机用户权限。
- 业务后端根据登录用户权限，将需要展示的 OSS key 转换为短期签名 URL。
- 手机端优先读取 `display_result`；后台管理与排错页面可读取完整 `raw_result`。

## 5. 失败与清理策略

- OSS 下载失败、算法失败、非法上传路径或任一文件上传失败时，返回 `status: "failed"` 和明确错误信息。
- 失败任务保留本地运行目录，方便排错。
- 所有结果上传成功后，Worker 才清理本次本地运行目录；OSS 中的完整结果不受影响。

## 6. 发给后端开发确认

```text
皱纹检测通过 Celery 对接，请确认：

1. Queue 和 Task Name 是否按 SERVICE_NAME 约定。
2. 投递参数为 task_id、oss_key、oss_result_prefix（可选）、algorithms（可选）。
3. 后端通过 Celery AsyncResult 获取结果，还是需要另行回调？
4. raw_result 是全部产物，需一次性接收和保存；display_result 是当前用户展示图标记。
5. 额头纹、眉间纹、鱼尾纹等动态分区图同时存在于 raw_result 和 display_result.regions。
6. display_result.regions 已附带完整量化指标，并按 relative_score 降序排列。
7. Worker 返回私有 OSS key，由后端按用户权限生成临时签名 URL。
8. 请确认签名 URL 有效期、任务结果保存期、失败重试次数和同 task_id 覆盖规则。
9. 请确认手机上传大小、支持格式和拍照方向纠正由哪一层负责。
```

## 7. 发给运维确认

```text
皱纹检测 Worker 部署请确认：

1. Ubuntu 24.04 x86_64 CPU 环境。
2. 使用 scripts/bootstrap_uv.sh 和 uv.lock 部署，执行 uv sync --frozen。
3. Redis broker/backend 地址与密码。
4. SERVICE_NAME 是否固定为 wrinkle-detection-worker。
5. OSS endpoint、bucket、AccessKey 与业务后端环境是否一致。
6. OSS Bucket 使用私有读权限，完整 raw_result 均需成功上传。
7. soft timeout=120 秒、hard timeout=150 秒是否符合平台规范。
8. balanced 单任务约 20 秒，请确认 Worker 并发数、CPU 核数及队列积压告警。
9. 请确认日志位置、失败任务告警及 OSS 结果保留周期。
```
