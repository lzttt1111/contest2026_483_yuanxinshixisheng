## 0. `run.py` 九项批量程序使用说明（先看这里）

### 0.1 程序用途

根目录的 `run.py` 是九项皮肤检测的大批量点火入口，适合单机或多台 GPU 电脑处理几十万张图片。它会对每张图片执行：

```text
红区、斑点、棕区、纹理、毛孔、UV色斑、紫质、皱纹、痤疮
```

程序支持 GPU 服务常驻、失败隔离、断点续跑、稳定分片、跨机器抢占防重复和常量内存流式统计。它是本地/服务器批处理入口，不会改变云端 Worker 的 Task、Queue 或五字段信封。

输出有两种模式：

- `review`：保存每张图片的九项正式结果，供人工验收。
- `scoring`：仅保存逐图状态和评分特征 JSONL，供几十万张常模统计；不复制输入图、不保留中间图，也不会生成数千万个小文件。

### 0.2 最常用启动命令

输入目录和输出目录必须明确指定，不再使用隐式默认路径：

```bash
cd /workspace/dermavision

uv run --frozen python run.py \
  --input-dir /mnt/aisia-images \
  --output-dir /mnt/aisia-results \
  --job-name skin-380k \
  --output-profile scoring
```

- `--input-dir`：待检测图片根目录，可以是本地目录或服务器共享图片目录的挂载点。
- `--output-dir`：检测结果根目录，可以是本地目录；多机协同时必须是所有机器共同可写的同一个共享目录。
- `--job-name`：本次批处理任务名。断点续跑时保持相同名称，便于查找状态和汇总。
- `--output-profile scoring`：38 万张评分分布任务必须使用；若要查看逐图正式结果才改为 `review`。
- `--output` 仍是 `--output-dir` 的兼容别名，但新命令建议统一使用 `--output-dir`。

如果图片存储在数据库、OSS 或其他对象存储中，必须先通过现有下载服务把它们提供为文件目录，或将远端文件系统挂载成目录；当前 `run.py` 的输入是文件夹路径，不直接执行 SQL 或读取 OSS key 列表。

### 0.3 输出目录结构

#### 评分统计模式（38 万张推荐）

```text
/mnt/aisia-results/_batch/skin-380k/
├── state.<worker-id>.jsonl
├── scoring_features.<worker-id>.jsonl
├── skin-380k.<worker-id>.summary.json
├── skin-380k.<worker-id>.summary.csv
└── failures/                       # 仅失败索引/耗时，不含输入和调试图片
```

状态、评分特征和汇总均逐行写入，运行进程不在内存中保存十几万条结果。评分 JSONL 可直接断点导入 SQLite：

```bash
uv run --frozen python scripts/scoring/update_score_statistics.py \
  --jsonl /mnt/aisia-results/_batch/skin-380k/scoring_features.gpu-pc-01.jsonl \
  --jsonl /mnt/aisia-results/_batch/skin-380k/scoring_features.gpu-pc-02.jsonl \
  --jsonl /mnt/aisia-results/_batch/skin-380k/scoring_features.gpu-pc-03.jsonl \
  --database calibration/population_metrics.sqlite3
```

#### 人工验收模式

默认每 2000 张图片保存在一个大批次目录中，38 万张图片会形成 190 个 `batch_xxxxxx` 目录：

```text
/mnt/aisia-results/
├── batch_000001/
│   ├── 图片000001/                 # 该图片的九项正式结果
│   ├── 图片000002/
│   └── ...                         # 本批次最多 2000 张
├── batch_000002/
│   └── ...
├── .runtime/                       # 正在运行的临时产物
└── _batch/
    ├── _claims/                    # 多机原子抢占锁
    └── skin-380k/
        ├── state.<worker-id>.jsonl # 每完成一张立即写入状态
        ├── skin-380k.<worker-id>.summary.json
        └── skin-380k.<worker-id>.summary.csv
```

每张正式结果目录还会写入 `批处理元数据.json`，记录原图片相对路径、文件大小、修改时间及所属批次，用于跨机器断点核验。可以通过以下参数修改每组数量：

```bash
--images-per-group 2000
```

### 0.4 断点续跑

断点续跑默认开启。程序每处理完一张就立即 `fsync` 状态文件，并同时检查正式结果目录中的 `九项检测结果索引.json` 和 `批处理元数据.json`。

任务因断电、网络或人工中断而停止后，直接重新执行完全相同的命令：

```bash
uv run --frozen python run.py \
  --input-dir /mnt/aisia-images \
  --output-dir /mnt/aisia-results \
  --job-name skin-380k \
  --output-profile scoring
```

输入图片相对路径、文件大小和修改时间均未变化且结果完整时会自动跳过；图片发生变化或正式结果缺失时会重新处理。需要强制重新运行选中图片时使用 `--no-resume`。

### 0.5 多台电脑并行运行

假设使用三台电脑：所有机器必须看到相同的输入图片相对路径，并共同使用同一个共享输出目录。三台电脑使用相同的 `--shard-count 3`，分别使用不同的 `--shard-index`：

```bash
# 第1台：gpu-pc-01
uv run --frozen python run.py \
  --input-dir /mnt/aisia-images --output-dir /mnt/aisia-results \
  --job-name skin-380k --output-profile scoring \
  --shard-count 3 --shard-index 0 --worker-id gpu-pc-01

# 第2台：gpu-pc-02
uv run --frozen python run.py \
  --input-dir /mnt/aisia-images --output-dir /mnt/aisia-results \
  --job-name skin-380k --output-profile scoring \
  --shard-count 3 --shard-index 1 --worker-id gpu-pc-02

# 第3台：gpu-pc-03
uv run --frozen python run.py \
  --input-dir /mnt/aisia-images --output-dir /mnt/aisia-results \
  --job-name skin-380k --output-profile scoring \
  --shard-count 3 --shard-index 2 --worker-id gpu-pc-03
```

防止重复计算有两层机制：

1. 根据图片相对路径 SHA-256 稳定分片，正常配置下同一图片只属于一个分片。
2. `_batch/_claims/` 使用原子目录锁。即使两台机器误用了相同 `shard-index`，也只有一台能取得该图片的处理权，另一台记录 `claimed_elsewhere` 后跳过。

异常关机遗留的锁默认 21600 秒（6小时）后可以被其他节点接管，可通过 `--claim-timeout-seconds` 调整。不要把超时时间设得小于单张图片可能出现的最长处理时间。

如果多台电脑分别写入自己的本地输出目录，抢占锁不能跨机器生效；这种情况下必须由运维保证每台机器的 `shard-index` 唯一。正式任务推荐使用服务器共享输出目录。

### 0.6 全部命令行参数

| 参数 | 默认值 | 作用 |
|---|---:|---|
| `--input-dir PATH` | 无，必填 | 输入图片根目录 |
| `--output-dir PATH` | 无，必填 | 正式输出根目录；`--output` 为兼容别名 |
| `--job-name NAME` | `nine-analysis-batch` | 状态和汇总任务名 |
| `--output-profile MODE` | `review` | `review` 保存逐图结果；`scoring` 只保存评分 JSONL |

| `--glob PATTERN` | 不限制 | 文件名/相对路径过滤，可重复传入 |

### 5.1 九项大批量点火程序

`run.py` 用于几十万张图片的正式批处理。输入目录和输出目录没有隐式默认值，启动时必须明确指定：

```bash
cd /workspace/dermavision

  --input-dir /data/skin-images \
  --output-dir /data/skin-analysis-results \
  --job-name skin-380k \
  --output-profile scoring
```

参数含义：

| 参数 | 必填 | 说明 |
|---|---|---|
| `--input-dir PATH` | 是 | 输入图片根目录，默认递归扫描 JPG/JPEG/PNG/BMP/WEBP |
| `--output-dir PATH` | 是 | 正式结果根目录；旧名称 `--output` 仍可兼容使用 |
| `--job-name NAME` | 否 | 断点状态和汇总任务名，建议每批数据使用固定名称 |
| `--output-profile MODE` | 否 | 38万统计用 `scoring`；逐图验收用 `review` |
| `--precount` | 否 | 完整预扫描；NFS大库保持关闭 |
| `--images-per-group N` | 否 | 每个批次目录最多容纳的逐图结果数，默认 `2000` |
| `--resume/--no-resume` | 否 | 是否按相对路径、大小和修改时间断点续跑，默认开启 |
| `--shard-count/--shard-index` | 否 | 多进程或多机器稳定分片参数 |
| `--worker-id NAME` | 否 | 执行节点名称，多机运行时建议显式设置为唯一机器名 |
| `--claim-timeout-seconds N` | 否 | 共享锁异常恢复时间，默认 21600 秒（6小时） |

`scoring` 输出布局：

```text
/data/skin-analysis-results/_batch/
    └── skin-380k/
        ├── state.<worker-id>.jsonl  # 各节点独立、逐张落盘的断点状态
        ├── scoring_features.<worker-id>.jsonl
        ├── skin-380k.<worker-id>.summary.json
        └── skin-380k.<worker-id>.summary.csv
```

`scoring` 不生成逐图结果目录；`review` 才按每 2000 张生成一个
`batch_xxxxxx`。任务中断后重新执行相同命令即可续跑。

### 5.2 多台电脑共同处理服务器图片

如果图片位于服务器文件库，先将图片目录以只读方式挂载到所有计算机，并将同一个结果目录以可写方式挂载到所有计算机。所有节点必须看到一致的图片相对路径和同一个共享输出目录。

三台电脑的启动示例：

```bash
# gpu-pc-01
uv run --frozen python run.py \
  --input-dir /mnt/aisia-images --output-dir /mnt/aisia-results \
  --job-name skin-380k --output-profile scoring \
  --shard-count 3 --shard-index 0 --worker-id gpu-pc-01

# gpu-pc-02
uv run --frozen python run.py \
  --input-dir /mnt/aisia-images --output-dir /mnt/aisia-results \
  --job-name skin-380k --output-profile scoring \
  --shard-count 3 --shard-index 1 --worker-id gpu-pc-02

# gpu-pc-03
uv run --frozen python run.py \
  --input-dir /mnt/aisia-images --output-dir /mnt/aisia-results \
  --job-name skin-380k --output-profile scoring \
  --shard-count 3 --shard-index 2 --worker-id gpu-pc-03
```

防重复采用两层机制：

1. 相对路径 SHA-256 稳定分片，正常配置时同一张图片只属于一个节点。
2. 共享输出目录 `_batch/_claims/` 使用原子目录锁；即使两台电脑误用相同分片，只有一个节点能够取得图片处理权。

`scoring` 状态记录直接保存输入相对路径、大小和修改时间；`review` 还会在
逐图结果中写入 `批处理元数据.json`。节点异常退出后的锁默认 6 小时后可由
其他节点接管。

如果各电脑使用的是彼此独立的本地输出目录，原子抢占锁无法跨机器生效，此时必须保证 `--shard-index` 唯一；正式批处理推荐始终使用服务器共享输出目录。

只查看完整命令行说明，不启动模型：

```bash
uv run --frozen python run.py --help
```
