# 九项评分标定技术方案

## 1. 医生资料采用顺序

1. `Markdown-7.24补充指标` 中的专项需求和汇总报告 V2 为当前正式医学指导。
2. `皮肤检测指标` 根目录的四份 DOCX 作为早期版本交叉核对，不覆盖7月24日补充口径。
3. 医生给出的权重是第一版指导权重，不是已经验证的医学阈值。

## 2. 评分方向

除医生模板另有说明外，九项均采用“问题表型负担分”：0分表示未见明显，100分表示图像表型更明显。分数高低不能跨项目直接比较，也不能作为疾病诊断。

## 3. 为什么不能直接给正式分数

- 目前没有九项共同的参考人群分布。
- 38万张图片可能存在重复受检者、拍摄设备差异、曝光差异和人群选择偏倚。
- 当前UV色斑和紫质来自白光模拟图层，不是真实UV或荧光采集。
- 当前纹理和皱纹缺少真实3D高度/深度以及多角度稳定性证据。

因此第一阶段输出原始量化指标和 `uncalibrated`；参考分布生成后再启用候选评分。

## 4. 38万张参考分布流程

1. 建立只含路径和人群元数据的数据清单，原图不进入Git。
2. 使用常驻GPU九项流水线分片运行，每片建议1000张，可断点续跑。
3. 排除REJECT图片；WARNING与PASS分别统计。
4. 使用SHA-256与感知哈希去重；同一受检者重复图片按受检者加权，避免高频用户主导常模。
5. 先运行1000张试验批次，确认失败率、耗时、指标缺失和分布方向，再运行全量。
6. 对数量、密度、面积和连续长度等偏态指标应用 `log1p`，按0.5%和99.5%分位稳健截尾。
7. 建立总体常模；具备年龄、性别、肤质和设备信息时建立分层常模。分层有效样本少于1000时回退总体常模。
8. 每个原始指标转换为“问题负担百分位”，再按 `metric_registry.json` 的医生指导权重合成项目候选评分。
9. 采用0～20、21～40、41～60、61～80、81～100五档作为候选图像学等级，经医生抽样复核后锁定评分版本。

少量人工验收可继续为每张图片生成 `scoring_features.json`。38 万张正式
分布任务使用 `run.py --output-profile scoring`，每台机器只产生一份
`scoring_features.<worker-id>.jsonl`，再由 `scripts/scoring/update_score_statistics.py
--jsonl` 流式、幂等地写入 SQLite。计数、密度、面积和长度类指标先做
`log1p`，0.5%/99.5% 分位作为稳健边界；比例和0～1强度保持原尺度。

程序默认要求每个参与指标至少1000个有效样本。低于门槛只生成
`insufficient_samples` 审计文件，不允许进入候选评分。该门槛并不替代医生验证。

## 5. 统计边界

38万张分布只能建立AISIA内部参考人群的相对常模，不能证明“医学正常”。正式等级至少需要医生对分层抽样集进行盲评，检查排序、边界病例和重复拍摄稳定性。

当前不输出九项总分。若后续需要综合总分，必须由医生确认九项之间权重，并处理色斑、棕区、UV色斑以及红区、痤疮、紫质之间的重复证据。
