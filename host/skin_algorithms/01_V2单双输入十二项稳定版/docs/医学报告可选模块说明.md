# 医学报告可选模块说明

## 定位

医学报告模块只负责汇总同一张图片已经完成的九项检测结果，生成内部复核 JSON
和 DOCX。它不重跑算法、不改变九项指标，也不参与几十万张参考分布计算。

当前报告属于基础版本，后续仍需按医生意见迭代版式、章节和解释。综合得分与程度
等级在参考人群分布和医生标注完成前固定显示为“待医学标定”。

## 默认行为

常规九项运行不会生成医学报告：

```bash
uv run --frozen python scripts/review/run_nine_analysis.py \
  --input-dir data/test_images \
  --output output \
  --layout archive
```

该默认行为适用于几十万张图片批处理，只输出九项算法结果、量化指标、评分特征和
耗时信息。

## 单独生成报告

九项人工验收结果全部成功后执行：

```bash
uv run --frozen python scripts/report/run_medical_report.py \
  --result-dir output-test/<图片名称> \
  --subject-id <受检者编号>
```

输出位于：

```text
output-test/<图片名称>/医学报告/
├── AISIA_面部多指标检测报告_<报告编号>.json
└── AISIA_面部多指标检测报告_<报告编号>.docx
```

也可在单次 `review` 运行中显式增加 `--generate-medical-report`。该开关不允许与
`archive` 模式组合，防止批量任务误生成大量 DOCX。

## 输入和校验

- 输入目录必须存在 `九项检测结果索引.json`。
- 索引必须为 `9/9 success`，否则明确失败，不生成不完整报告。
- 红区、斑点、棕区、纹理、毛孔、痤疮和皱纹读取当前正式量化 JSON。
- 紫外线色斑和紫质保留在九项结果索引中；当前医生 V2 报告没有对应独立章节，
  后续模板升级时再增加正式展示章节。
- 报告 JSON 是 DOCX 的唯一数据来源。

## 环境

报告模块复用项目根目录统一环境。`python-docx==1.2.0` 与 `lxml==6.1.1` 已固化
到根 `uv.lock`，不维护第二套虚拟环境。
