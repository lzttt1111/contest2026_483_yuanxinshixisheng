# 单RGB十二项运行与云端增量对接说明

更新：2026-08-20

## Acne v2 迁移合同（部署前必读）

acne v2 是独立新合同，不是对 acne v1 的就地修改。后端必须以
Queue/Task/信封版本成套路由：

| 合同 | Worker target | Queue | Task | `schema_version` | `meta_data` |
|---|---|---|---|---|---|
| acne v1（回滚线） | `acne` | `acne` | `acne.analyze_image` | `"1"` | `{"name":"acne","version":"1"}` |
| acne v2 | `acne_v2` | `acne_v2` | `dermavision.analyze_image` | `"2"` | `{"name":"acne","version":"2"}` |

两者的参数顺序均为
`task_id, oss_key, oss_result_prefix, algorithms`。acne v2 成功信封仍为顶层六字段，
`raw_result` **严格且仅**包含：

```text
overlay, metrics, quality_score, quality_status, quality_flags
```

- `overlay`：由 v1 `debug_info.display_result.overlay_original` 对应的正式圈选图合并而来，改为
  `raw_result` 内唯一媒体 OSS key。
- `metrics.疑似痤疮数量`：固定为
  `{总计,额头,左脸颊,右脸颊,鼻部,下巴}`，数值单位为个。
- `metrics.痤疮严重程度等级`：固定为 `{等级,注释}`。
- `quality_score`/`quality_status`/`quality_flags`：新的标准质量槽位；
  acne 暂无对应来源时分别为 `null`/`null`/`[]`，不得伪造分数。

### 发布、回滚与不变约束

1. 发布顺序必须为 `aisia-contracts -> ai-skin-backend -> DermaVision Worker`。
   契约仓未发布v2、后端未注册v2时，禁止启动 `acne_v2` Queue。
2. dev原名`dermavision-workers.target`现为默认V2，它使用
   `dermavision@acne_v2`；显式v1回滚target不得与其并行。
3. 回滚到v1时，先停止/禁用默认`dermavision-workers.target`并显式停止
   `dermavision@acne_v2`；再把后端投递路由切回 `acne`/`acne.analyze_image`，
   最后启用`dermavision-workers-v1.target`。不修改已发布的v1契约文件。
4. Word 生成在v1与v2都必须默认关闭；本迁移不修改 Word 模板、
   Word 代码或已冻结报告。
5. 旧8任务
   `redness/spots/brown/texture/pores/purple/acne/wrinkle` 的v1 Queue、Task、
   参数顺序、六字段信封、`raw_result`/`debug_info` 递归字段名与类型
   必须零漂移。acne v2 只通过新 target/Queue/Task/版本路由进入。

## 最新结论

本版以同事 `dev@3cbd57e` 的单RGB八任务/九结果部署为基线，只做加法扩展：

- 旧 `run.py`、`dermavision.analyze_image` 四参数顺序、六字段信封和八个旧 Worker 目标不删除、不改名、不改类型。
- 新增 `surface_gloss`、`vascular`、`contour_firmness` 三个单RGB Worker，从 8 任务/9 结果增加为 11 任务/12 结果。
- 另以 `acne_v2` Queue/target 增加严格v2合同；旧 `acne` Queue/target 原样保留用于回滚。
- 生产默认不生成 Word；`run.py` 仅在完整十二项且显式传入 `--generate-medical-report` 时允许生成报告。
- 四光源、真实365、`analyze_capture` 和 `clinic_four_light` 不在本阶段。

## 本地点火

```bash
# 默认十二项，Word关闭
python run.py --input-dir <RGB目录> --output-dir <结果目录>

# 完全复现原九项
python run.py --input-dir <RGB目录> --output-dir <结果目录> --algorithms legacy-nine

# 指定新增项
python run.py --input-dir <RGB目录> --output-dir <结果目录> --algorithms vascular
```

`run.py` 在一次批处理中只冷启动需要的常驻服务一次，之后连续处理所有图片；不应每张图重启进程。

## 新增三项合同

三项均使用 `dermavision.analyze_image(task_id, oss_key, oss_result_prefix, algorithms)`，Queue 与算法名同名。成功信封仍为：

```text
record_id,status,schema_version,meta_data,raw_result,debug_info
```

`raw_result` 固定字段：

```text
overlay,metrics,medical_report_csv_v2,quality_score,quality_status,quality_flags
```

`debug_info.report_csv` 指向简版CSV。新增三项`metrics`在正式发布前固定为
强类型中文前端精简指标；内部完整V2评分证据不塞入前端`metrics`。

| 算法 | 精简指标 | 中文口径 |
|---|---|---|
| surface_gloss | `油光面积占比.{总计,额头,左脸颊,右脸颊,鼻部,下巴}`、`油光区域数量.{...}` | 面积占比单位为0～1比例，区域数量单位为个 |
| vascular | `血管样结构数量.{总计,额头,左脸颊,右脸颊,鼻部,下巴}`、`血管样结构总长度.{...}` | 数量单位为个，长度单位为1024标准化图像像素 |
| contour_firmness | `中面部曲面连续性`、`下颌缘连续性`、`左右轮廓差异` | 相对代理值（0～1），非真实紧致度或组织位移 |

## 三仓发布顺序

1. `aisia-contracts`：先发布包含新增三项v1模块与 acne v2 模块的不可变标签，不修改已发布v1文件。
2. `ai-skin-backend`：先注册合同、队列提交和中文前端映射，并保留 acne v1 路由。
3. `DermaVision`：更新契约依赖后才可启用默认`dermavision-workers.target`。

本工作树只包含DermaVision侧的合同快照和对接代码；当前项目SSH Key尚未获得Codeup契约仓读权限，
且 `uv.lock` 尚未完成可复现更新，因此不能伪称新契约标签已发布，也不得进入部署。

## 部署文件

- `run_cloud_worker.py`：增加 `acne_v2` 可指定target，旧target不变。
- `deploy/dermavision@.service`：唯一模板；本迁移不修改其行为。
- `deploy/dermavision-workers.target`：保持dev原名的默认V2集合，使用
  `dermavision@acne_v2`。
- `deploy/dermavision-workers-v1.target`：新增的显式回滚集合，使用旧acne实例。
