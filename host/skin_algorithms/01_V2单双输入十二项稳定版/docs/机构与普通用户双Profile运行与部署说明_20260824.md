# DermaVision 机构与普通用户双Profile运行与部署说明

更新时间：2026-08-24

## 1. 路由原则

本仓库只有一套算法源码，通过显式Profile选择成像策略：

- `institution`：现有机构仪器RGB_M流程；红区、棕区和血管继续使用已验收厂家RED/BROWN链。
- `consumer`：普通手机RGB流程；红区和棕区直接使用对齐后的原始RGB，血管使用单RGB引擎，不加载厂家sidecar。

正式环境禁止根据分辨率、文件大小、EXIF或图像风格自动猜Profile。后端必须根据业务入口选择Queue。现有Queue永久表示institution；consumer只通过加法Queue提供。

## 2. 本地启动

机构版保持默认命令：

```bash
.venv/bin/python run.py \
  --input-dir /data/institution-rgb-m \
  --output-dir /data/results/institution \
  --capture-profile institution
```

`--capture-profile`不写时默认`institution`。

普通用户：

```bash
.venv/bin/python run.py \
  --input-dir /data/consumer-rgb \
  --output-dir /data/results/consumer \
  --capture-profile consumer
```

两个Profile必须使用不同输出根。断点签名包含Profile，同一图片的机构结果不能让consumer任务错误跳过。

institution与consumer在本地`review`完整十二项运行中默认生成用户版、医生版双Word，可用`--no-generate-medical-report`显式关闭；`scoring`批量标定和云端Worker默认关闭Word。consumer当前评分为未完成人群标定的工程代理，不得表述为医学常模或诊断结论。

## 3. 云端Queue与Task

旧机构Queue、Task、四参数和六字段信封完全不变。consumer使用同Task、同参数和同字段类型，只新增Queue：

| 检测 | institution Queue | consumer Queue | Task |
|---|---|---|---|
| 红区 | `redness` | `consumer_redness` | `dermavision.analyze_image` |
| 斑点 | `spots` | `consumer_spots` | `dermavision.analyze_image` |
| 棕区 | `brown` | `consumer_brown` | `dermavision.analyze_image` |
| 纹理 | `texture` | `consumer_texture` | `dermavision.analyze_image` |
| 毛孔 | `pores` | `consumer_pores` | `dermavision.analyze_image` |
| UV/卟啉 | `purple` | `consumer_purple` | `dermavision.analyze_image` |
| 痤疮V2 | `acne_v2` | `consumer_acne_v2` | `dermavision.analyze_image` |
| 皱纹 | `wrinkle` | `consumer_wrinkle` | `wrinkle.analyze_image` |
| 油光 | `surface_gloss` | `consumer_surface_gloss` | `dermavision.analyze_image` |
| 血管 | `vascular` | `consumer_vascular` | `dermavision.analyze_image` |
| 轮廓 | `contour_firmness` | `consumer_contour_firmness` | `dermavision.analyze_image` |

四参数仍为：

```text
task_id, oss_key, oss_result_prefix, algorithms
```

成功信封仍为：

```text
record_id, status, schema_version, meta_data, raw_result, debug_info
```

consumer不增加前端字段；DermaVision consumer任务仅把既有`debug_info.execution_mode`值设为`single_algorithm_consumer`。Queue是后端选择Profile的权威来源。

## 4. systemd启动

机构默认：

```bash
sudo systemctl enable --now dermavision-workers.target
```

普通用户：

```bash
sudo systemctl enable --now dermavision-consumer-workers.target
```

同一GPU禁止同时启动两套target。unit已声明`Conflicts`；切换时仍应先停止当前集合并确认GPU进程退出：

```bash
sudo systemctl disable --now dermavision-workers.target
sudo systemctl enable --now dermavision-consumer-workers.target
```

consumer不要求厂家sidecar；institution仍必须配置并校验：

```text
DERMAVISION_VENDOR_SKIN_MODULES_ROOT
DERMAVISION_VENDOR_SKIN_MODULE_SHA256
```

## 5. 公共Mask合同

`analysis_mask_bundle_v1`记录有效皮肤、头发、面部毛发、五官、鼻孔和显示域SHA。规则：

- 算法最终Mask必须是公共有效皮肤Mask的子集。
- 各算法可追加排除，禁止通过闭运算、凸包或显示Mask重新引入毛发。
- 显示底图可保留头发；检测Marker、计数和分母不得落入毛发。
- consumer acne/wrinkle在各自标准化坐标内复用同一毛发实现；institution保留历史Mask行为。

consumer额头毛发覆盖达到门限时添加`FOREHEAD_OCCLUDED`，额头区域不参与检测、计数和指标分母；展示图仍保留完整连续的VISIA轮廓，不用计算Mask裁断展示线。强局部照明添加`SEVERE_LOCAL_LIGHTING`并REJECT。

consumer侧脸显示固定使用当前VISIA侧脸闭合线（A风格），不使用dev的全可见肤区外轮廓（B风格）。A/B对比使用同一批毛孔Marker和同一份指标，对比证据仅位于Git外验收目录。侧脸仍检测全部可评估模块；依赖双侧几何的轮廓紧致度不可评估时，只标记该单项失败，不删除其他已成功结果。

## 6. 红棕及血管差异

institution完全保留当前厂家效果。consumer：

- 红区/棕区不调用`core.skin_generate`，不产生`RED_M.jpg/BROWN_M.jpg`中间JPEG。
- 现有RBX/Brown检测与量化代码继续复用，只改变其输入Style。
- 血管使用`VascularStructure-V2.1-ConsumerRGB`，公开仍只有“数量”和“标准化总长度”。

## 7. 评分、零目标和Word

- institution与consumer统一使用`production_proxy_v1`和同一137项显式公式，但不得把缺失证据的模块伪造为有效分数。
- 当前consumer固定正脸样本可11/11`score_valid=true`；institution当前四光源投影样本只有2/11有完整公式输入，其余9项必须`score=null/grade=不可评估/score_valid=false`，待后续单RGB↔四光源评分映射。
- 当前分数仅使用3个冻结锚点归一化，非人群常模、非医学阈值，Word必须与根完整JSON使用同一Profile和`score_valid`。
- 目标数量、面积、长度为真实0时保留0；不存在实例的P50/P90分布值为`不可评估`。
- institution与consumer本地review默认生成双Word；云端Worker默认关闭Word。

## 8. 后端对接与发布门禁

后端只需增加consumer Queue路由，不得修改旧Queue。公开字段形状不变，因此不应通过改变旧`aisia-contracts`模型实现分流。部署前必须证明：

1. 后端机构入口只投递旧Queue，普通用户入口只投递`consumer_*`。
2. 两个target各11实例，不能同时占用同一GPU。
3. institution固定三套结果和Word零漂移。
4. consumer 22张验收包含QC拒绝、Mask交集、红棕块效应及字段检查。

未取得真实backend路由发布证据前，可以推送功能分支供审核，但禁止宣称生产联合部署完成。
