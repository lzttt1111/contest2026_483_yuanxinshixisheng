# 水光三项云端服务部署与接口说明

版本：`shuiguang-three-score-service 0.1.0`  
适用目录：本文件所在的 `02_水光三项三视图服务` 目录  
当前实现：只运行毛孔、可见色斑、表面油光；不运行痤疮、皱纹、棕区、UV、四光源或目标检测。

## 1. 给调用方的一句话说明

调用方准备同一受检者的三张 RGB 三视图照片（左侧、正面、右侧，提交时可以乱序），调用方先把照片保存到服务允许的输入目录，再提交一个 JSON 任务。服务自动判断三张照片的正面和左右侧，实际评分只使用正面照片，最后异步返回一个**只包含三项整体评分、分区评分和严重程度的 JSON**。返回结果不包含图片、Mask、特征点或 Word 文件。

当前默认使用 BiSeNet 预处理。由于时间限制，本版本不重跑1000例：新预处理正常计算；个别没有匹配参考的分区，使用包内已经保存的旧评分回退文件补齐。因此返回可以立即上线使用，但诊断入口中的 `reference_matches_new_preprocessing` 仍为 `false`，不能称为新预处理已重新标定。以后完成新参考后，只需替换参考配置并关闭回退，不需要改调用合同。

## 2. 处理链路

```text
三张 RGB 照片
    │  输入校验、SHA256、路径越界检查
    ▼
方向识别（自动找出 front / left / right）
    │  仅保存三张任务输入，不保存连续视频
    ▼
常驻 Celery worker（CUDA）
    │  BiSeNet 人脸/皮肤预处理
    │  仅 pores + spots + surface_gloss 三条检测链
    ▼
正面量化与评分
    │  新预处理结果优先；缺失分区读取 legacy_score_fallback.json
    ▼
ScoreResponse JSON
```

三项检测在同一个常驻 worker 进程中执行。worker 首次启动会加载模型，后续任务复用已加载的执行器；不要为每张照片重新启动 Python 进程。当前代码、模型、V3 必要评分代码和回退文件均放在本目录 `vendor` 下，运行时不从 D 盘旧项目、父目录业务代码或共享虚拟环境导入。

## 3. 从零准备服务器

### 3.1 推荐运行条件

- Linux x86_64（已验收环境为 Ubuntu 22.04）；
- Python 3.10；
- NVIDIA 驱动和可用 CUDA GPU，服务配置使用 `cuda:0`；
- Redis：一个 broker 数据库和一个 result backend 数据库；
- 安装 `uv`；
- 至少 8 GB 可用磁盘空间用于环境、模型和运行时结果；
- 服务器有权限监听内部网地址，但不要直接暴露到公网。

本目录内有 `uv.lock`，依赖必须锁定安装。不要用 `pip install -U` 随意升级 Torch、OpenCV、NumPy 或 Celery。

### 3.2 安装依赖

```bash
cd /path/to/02_水光三项三视图服务
uv sync --locked
```

安装前可检查锁文件：

```bash
uv lock --check --offline
```

如果目标机没有 NVIDIA 驱动，不能把 CPU 跑通当作云端正式性能验收；应先准备 GPU。模型文件位于：

```text
vendor/v3/models/face_parsing_resnet18.onnx
```

模型 SHA256：`0d9bd318e46987c3bdbfacae9e2c0f461cae1c6ac6ea6d43bbe541a91727e33f`。部署前建议核对：

```bash
sha256sum vendor/v3/models/face_parsing_resnet18.onnx
```

### 3.3 设置环境变量

以下变量必须在 worker 和 API 网关两个终端中保持一致：

```bash
export SHUIGUANG_INPUT_ROOT="$PWD/runtime/inputs"
export SHUIGUANG_RUNTIME_ROOT="$PWD/runtime"
export SHUIGUANG_CLOUD_DEVICE="cuda:0"
export SHUIGUANG_PREPROCESS_MODE="bisenet_rgb_diagnostic_v1"
export SHUIGUANG_FACE_PARSER_MODEL="$PWD/vendor/v3/models/face_parsing_resnet18.onnx"
export SHUIGUANG_LEGACY_SCORE_FALLBACK="1"
export SHUIGUANG_PRELOAD="1"
export SHUIGUANG_BROKER_URL="redis://127.0.0.1:6379/0"
export SHUIGUANG_RESULT_BACKEND="redis://127.0.0.1:6379/1"
mkdir -p "$SHUIGUANG_INPUT_ROOT" "$SHUIGUANG_RUNTIME_ROOT"
```

`SHUIGUANG_LEGACY_SCORE_FALLBACK=1` 是当前上线兼容配置。它只补齐新预处理没有分数的区域，不覆盖新结果。设置为 `0` 会关闭回退；此时新预处理没有正式匹配参考时，正式接口会返回 `SCORING_REFERENCE_NOT_READY`。

## 4. 启动服务

### 4.1 启动 Celery worker

在第一个终端执行：

```bash
uv run --no-sync celery -A cloud_three.tasks:app worker \
  --pool=solo --concurrency=1 \
  -Q shuiguang_diagnostic,shuiguang_scores \
  --loglevel=INFO
```

看到 `worker ready` 后才提交任务。一个 GPU 上首版只启动一个 worker、一个并发；不要启动多个 worker 争抢同一模型和 GPU。队列含义如下：

| 队列 | 任务 | 用途 |
|---|---|---|
| `shuiguang_scores` | `shuiguang.analyze_three_views_scores` | 当前正式兼容上线入口 |
| `shuiguang_diagnostic` | `shuiguang.analyze_three_views_diagnostic` | 诊断/回归入口，响应带诊断元数据 |

### 4.2 启动 HTTP 网关

在第二个终端设置同样的环境变量后执行：

```bash
uv run --no-sync uvicorn cloud_three.api:app \
  --host 0.0.0.0 --port 8897
```

正式环境应在反向代理后加鉴权、上传大小限制、请求超时和 HTTPS；不要把这个无认证的开发网关直接暴露公网。网关只负责校验请求、投递 Celery 和查询结果，不在 API 进程中执行模型。

## 5. 输入：三张照片

### 5.1 文件保存规则

调用方（上传层或业务后端）先将三张照片保存到 `SHUIGUANG_INPUT_ROOT` 下的任务目录，再把**相对于该目录的路径**放入请求。服务不会读取任意 Windows/Linux 绝对路径，也不会从请求路径跳出输入根目录。

照片要求：

- 必须是同一受检者的三张 RGB 照片；
- 可以是 JPEG 或 PNG，不能把三张图拼成一张；
- 每张照片有唯一 `image_id`；
- 提交顺序可以任意，不能用数组位置代替视角；
- 不要提交带网页画框、文字或裁剪缩略图的截图；
- `mirrored=true` 只表示输入是镜像自拍预览，服务会统一处理，保存的分析图不按预览镜像语义解释。

### 5.2 请求 JSON

`POST /api/score-jobs` 和 `POST /api/diagnostic-jobs` 使用相同请求体：

```json
{
  "task_id": "clinic_20260918_0001",
  "images": [
    {"image_id": "photo_a", "path": "clinic_20260918_0001/a.jpg"},
    {"image_id": "photo_b", "path": "clinic_20260918_0001/b.jpg"},
    {"image_id": "photo_c", "path": "clinic_20260918_0001/c.jpg"}
  ],
  "mirrored": false
}
```

字段说明：

| 字段 | 类型 | 中文说明 |
|---|---|---|
| `task_id` | string | 业务任务唯一 ID，1—64 位，只允许字母、数字、下划线、连字符；用于幂等和结果目录。 |
| `images` | array | 必须恰好三项，同一受检者的三张照片；服务自动判定视角。 |
| `images[].image_id` | string | 原始照片追踪 ID，三张不能重复；不代表正面或侧面。 |
| `images[].path` | string | 相对于 `SHUIGUANG_INPUT_ROOT` 的文件路径；不要传绝对路径。 |
| `mirrored` | boolean | 是否来自镜像自拍预览；普通原图填 `false`。 |

服务会检查三张图片存在、SHA256、尺寸和方向。没有明确找到一张正面及左右侧脸时，任务失败，不会猜测并返回假结果。

## 6. HTTP 接口

### 6.1 健康检查

```http
GET /health
```

成功示例：

```json
{
  "status": "ok",
  "service": "shuiguang_three",
  "algorithms": ["pores", "spots", "surface_gloss"],
  "legacy_score_fallback": true
}
```

### 6.2 提交正式兼容任务

```http
POST /api/score-jobs
Content-Type: application/json
```

HTTP 202 示例：

```json
{
  "task_id": "clinic_20260918_0001",
  "queue_id": "Celery任务UUID",
  "status": "queued",
  "score_source": "bisenet_with_legacy_fallback"
}
```

### 6.3 查询正式结果

```http
GET /api/score-jobs/{queue_id}
```

任务执行中会返回 `queue_id/status/progress`；成功时只返回第7节的三项目 JSON；失败时返回：

```json
{
  "status": "failed",
  "task_id": "clinic_20260918_0001",
  "error": {"code": "ORIENTATION_UNCERTAIN", "message": "未能明确识别一张正面及左右侧脸"}
}
```

### 6.4 诊断入口

`POST /api/diagnostic-jobs` 与 `GET /api/diagnostic-jobs/{queue_id}` 用于回归。它的结果外层会带 `schema_version`、`purpose`、`preprocessing`、`reference_matches_new_preprocessing` 和 `scores`；其中 `scores` 的字段与正式结果完全相同。诊断入口不应被前端当成另一套算法。

### 6.5 保留但不用于本服务的入口

- `/api/jobs`：旧版推理入口，新预处理下会拒绝；不要调用。
- `/api/v2/jobs`：历史三视图数量/绑定接口，不能替代当前三项评分入口。

## 7. 返回 JSON 与中文字段说明

正式接口成功时**只返回 JSON**，不返回三张图片：

```json
{
  "pores": {
    "name": "毛孔",
    "score": 57,
    "severity": "中度",
    "regions": [
      {"region": "forehead", "name": "额部", "score": 57, "severity": "中度"},
      {"region": "nose", "name": "鼻部", "score": 61, "severity": "轻度"}
    ]
  },
  "spots": {
    "name": "可见色斑",
    "score": 10,
    "severity": "显著",
    "regions": [
      {"region": "forehead", "name": "额部（含眉间）", "score": 3, "severity": "显著"}
    ]
  },
  "surface_gloss": {
    "name": "表面油光",
    "score": 73,
    "severity": "轻度",
    "regions": [
      {"region": "left_cheek", "name": "画面左面颊", "score": 100, "severity": "未见明显"}
    ]
  }
}
```

字段含义：

| 字段 | 中文说明 |
|---|---|
| `pores` | 毛孔项目对象。 |
| `spots` | 独立可见色斑项目对象，不进入 Brown/UV 混合链。 |
| `surface_gloss` | 纯表面油光项目对象，不是油脂分泌倾向项目。 |
| `name` | 项目或区域中文名称。 |
| `score` | 0—100 的状态分，分数越高表示状态越好；整体分使用正面照片。 |
| `severity` | 严重程度文字：`未见明显`、`轻度`、`中度`、`较明显`、`显著`。 |
| `regions` | 正面分区数组；侧脸只用于原有数量/视角判断，不产生本次区域评分。 |
| `regions[].region` | 稳定英文区域 ID，左右按照片画面定义。 |
| `regions[].score` | 该区域自己的评分，不是复制全脸分。默认兼容回退开启时，已知缺项不会返回 `null`。 |

区域数量和范围：

| 项目 | 正面分区 |
|---|---|
| 毛孔 | `forehead` 额部、`nose` 鼻部、`left_nasal/right_nasal` 画面左右鼻旁、`left_inner_cheek/right_inner_cheek` 左右内侧面颊、`left_outer_cheek/right_outer_cheek` 左右外侧面颊、`chin` 下巴，共9区。 |
| 可见色斑 | `forehead` 额部（含眉间）、`nose` 鼻部、`left_cheek/right_cheek` 左右面颊（含颧部、鼻旁）、`perioral` 口周、`chin` 下巴及下颌，共6区。 |
| 表面油光 | `forehead`、`nose`、`left_nasal/right_nasal`、`left_zygoma/right_zygoma` 左右颧部、`left_cheek/right_cheek` 左右面颊、`chin`，共9区。 |

评分方向固定为 `higher_is_better`。`null` 只表示关闭回退或确实没有可用依据，不能把 `null` 当成 0，也不能把它解释为“未检出目标”。

## 9. 幂等、失败和运维规则

1. 同一个 `task_id`、相同三张图和相同配置重复提交，返回已有结果，不重复启动推理。
2. 同一个 `task_id` 改了图片、镜像参数、预处理模式或回退配置，会返回 `TASK_ID_CONFLICT`；请使用新任务 ID。
3. 摄像头或上传层顺序错误不影响视角识别；多人、无正面、输入损坏或人脸方向不确定时任务失败，不猜测。
4. worker 重启不会覆盖旧任务结果；每个任务有自己的输入快照和结果目录。
5. 首次 worker 启动包含模型冷启动，后续任务复用常驻执行器；不要用每次新建 Python 进程的耗时评价稳态速度。
6. `runtime` 需要定期清理，但只能清理已完成且已归档的任务目录，不能删除运行中任务或评分参考。
7. 云端必须配置 Redis、认证、上传大小限制、超时和日志留存；本地文件系统 broker 只用于测试，不是生产队列。

## 10. 当前版本边界与后续替换点

本包是可立即联调和上线的三项兼容版本。它不重新计算1000例，也不声称 BiSeNet 参考已经重新拟合。旧评分回退文件位于 `vendor/legacy_score_fallback.json`，内部 trace 会记录哪些字段使用了回退。未来完成新的同口径参考后：

1. 生成并审核新的三项参考配置；
2. 替换对应 `vendor` 参考文件；
3. 设置 `SHUIGUANG_LEGACY_SCORE_FALLBACK=0`；
4. 重新执行本文件第8节三组测试；
5. 不改变输入 JSON、输出 JSON 或 Celery 任务名称。

本版本没有修改冻结 V2、医生 V3、06 号 Skill 沙箱，也不依赖打包目录外的业务代码或评分模块。
