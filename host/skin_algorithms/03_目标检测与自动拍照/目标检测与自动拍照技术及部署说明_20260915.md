# 目标检测与自动拍照技术及部署说明（2026-09-15）

## 1. 文档结论

本目录交付的是版本 `0.0.1` 的电脑端稳定基线，包含旧医美仪器检测、治疗头视觉接触点、人脸检测与空间锁定、头部角度估计、左右目标角度自动拍照、人脸七区及接触点落区、摄像头网页和定向测试。

当前状态固定为 `PC_FUNCTIONAL_BASELINE_RK3576_NOT_DEPLOYED`。它能在 Windows 浏览器采集摄像头、由 WSL2 Ubuntu 22.04 执行模型并显示结果；它不是RK3576固件，也没有真实云台控制、身份认证或皮肤诊断。

本目录采用已完成文件完整性验证的V0.0.1电脑端快照；运行源码、模型和板端参考均按清单记录SHA256，未经验证的候选文件不进入本版本。

## 2. 交付边界与模块调用链

```text
Windows Edge/Chrome getUserMedia
  -> 未镜像视频帧压缩为JPEG，最多一个请求在途
  -> 127.0.0.1:8876/v1/stream/frame
     -> X-Mode: face
        -> YuNet人脸检测 -> FaceLock空间连续性锁定
        -> 扩大ROI -> FSA-Net yaw/pitch/roll
        -> 中值+时间EMA -> CaptureGate质量/角度/稳定门
        -> 当前原始角度复核 -> 保存同一JPEG与JSON
     -> X-Mode: device
        -> V5 REAL-ONLY YOLOX-S旧仪器框
        -> 扩框ROI -> V5 MobileNetV3-Small接触点
        -> MediaPipe 468点 -> 七区标签 -> 接触点区域
  -> JSON返回网页，在显示层可选镜像
```

两种模式当前互斥。切换到 `face` 才运行角度和拍照状态机；切换到 `device` 才运行仪器、接触点和人脸分区。不要在汇报中写成五个模型每帧并行运行。

拍照是状态机，不是第三个神经网络。“人脸识别”在本项目中仅指人脸检测、空间连续性锁定和姿态估计，不包含身份注册、特征库、1:1或1:N身份认证。

## 4. 目标检测与接触点

### 4.1 设备检测

- 模型：`pc_demo/models/device/model.onnx`。
- 谱系：V5 REAL-ONLY YOLOX-S，目标是旧外观医美仪器。
- 输入：经EXIF方向校正的RGB图像；运行时转为640×640的YOLOX输入，填充值114，保持宽高比并在左上角对齐。
- 张量：FP32、NCHW；运行实现按现有代码执行BGR通道约定。
- 后处理：置信度阈值0.25，NMS阈值0.65，只保留最高设备候选。
- 输出：原始未镜像图像坐标中的 `device_bbox`、分数及模型/运行时信息。

历史固定测试集结果只用于说明该模型谱系：设备AP50约0.8945，召回93/102约0.9118，负样本0/2误报。测试集中负样本少、人物均为已知主体，不能改写成生产准确率。

### 4.2 接触点

- 模型：`pc_demo/models/contact/model.onnx`。
- 谱系：V5 MobileNetV3-Small接触点。
- 输入：设备框向外扩20%的ROI，缩放为256×256 RGB并使用ImageNet归一化。
- 输出：64×64热图、三类可见性；峰值周围半径3做加权解码，再映射回未镜像原图。
- 无设备框、可见性无效或结果过期时必须清空接触点。

历史V5测试口径为100个可评估点：归一化中位误差约1.80%，P90约3.87%，PCK@20约98.04%。该误差按扩展ROI对角线归一化，不是像素误差，也不证明治疗头与皮肤真实物理接触。

## 5. 人脸、角度与自动拍照

### 5.1 人脸检测和锁定

YuNet在BGR图像上检测人脸，默认检测输入上限640，置信度门限0.7；ROI约扩大1.35倍，额外上移约4%以包含额头。`FaceLock`用人脸框IoU维持同一空间轨迹，IoU门限0.30，短暂丢失恢复窗口350ms。多脸、候选跳变或长时间失锁时不会自动声称还是同一个人，操作员需要重置。

该锁定只利用空间连续性。系统不保存人脸特征，不建立身份库，不提供实名、注册或认证能力。

### 5.2 角度估计和防跳变

FSA-Net输入为扩大后的人脸ROI，BGR 64×64、NCHW，按 `(x-127.5)/128` 归一化，输出Yaw、Pitch、Roll。`PoseFilter`先取最近3帧中值，再按120ms时间常数做EMA；失脸或不连续时清空。

网页角度数字默认每1秒刷新一次，但摄像头推理、稳定进度和拍照判断仍按每个有效帧执行。展示降频不能被描述为推理降频。

### 5.3 拍照状态机

默认左右目标角度为绝对Yaw 45°，容差±5°，稳定时间500ms。Pitch和Roll默认要求在±12°内；至少连续3个有效样本；人脸最小尺寸80；帧间断超过350ms、结果年龄超过700ms、清晰度不足、失脸、侧别变化或角度快速跳变都会重置进度。触发前还会检查当前帧的原始角度，避免平滑值滞后导致误拍。

页面允许设置：目标角度5–80°、容差1–20°、Pitch/Roll上限5–45°、稳定时间300–3000ms；目标角度与容差之和不得超过89°。应用参数会开始新一轮会话。当前只保存 `left` 和 `right` 两槽，没有正面自动拍照槽。

保存内容位于运行时目录 `pc_demo/captures/<session_id>/`：触发帧JPEG和同名JSON。元数据含frame_id、单调捕获时间、Unix保存时间、raw_pose、稳定pose、实际门禁配置、清晰度、未镜像坐标约定和JPEG SHA256。该运行时目录不随参赛源码清单交付，也不得放入真人照片。

## 6. 人脸七区和额头覆盖

MediaPipe Face Landmarker生成468点，在 `device` 模式下构造七个展示区域：`forehead`、`subject_right_cheek`、`subject_left_cheek`、`chin`、`mouth_area`、`nose`、`eye_area`。额头沿人脸自身上下轴扩展约20%，而不是简单在屏幕Y方向画矩形；眼睛开口和嘴唇为排除区。

接触点按未镜像原图坐标映射到区域。自拍镜像只改变浏览器显示。多脸、几何退化、点落在边界、眼口排除区或脸外时返回unknown/excluded/outside_face等状态。

七区是几何关注区域，不是精确皮肤分割、发际线、血管避让、注射安全区或治疗建议。刘海、遮挡、大侧脸和强透视仍可能造成额头/脸颊偏差。

## 7. HTTP接口合同

主服务入口是 `pc_demo/server.py:create_app()`，由 `tools/run_server.py` 启动。

| 方法与路径 | 用途 |
|---|---|
| `GET /health` | 模型、provider、模型哈希与服务状态 |
| `GET /v1/debug/recent` | 最近数值记录，用于本机诊断 |
| `POST /v1/session` | 建立唯一活动会话并清空状态 |
| `POST /v1/session/{sid}/settings` | 更新目标角度、容差、倾斜和稳定时间 |
| `POST /v1/session/{sid}/reset?side=all|left|right` | 重置全部或单侧拍照状态 |
| `GET /v1/photos/{sid}/{filename}` | 读取本会话已保存照片 |
| `POST /v1/stream/frame` | 上传原始JPEG并返回face或device结果 |

帧请求使用 `Content-Type: image/jpeg`，并携带：

```text
X-Session-Id: <session UUID>
X-Mode: face | device
X-Frame-Id: <严格递增整数>
X-Capture-Ms: <浏览器 performance.now() 单调时间>
X-Frame-Age-Ms: <进入请求前已过去毫秒数>
```

服务校验JPEG头、解码、5MiB大小上限、1600万像素上限、会话、帧序号和年龄。非法请求返回400；旧会话、非递增帧或推理正忙等冲突返回409。它是单操作员本机服务，不是多租户云API。

`face`响应主要字段为：图像尺寸、face框、`raw_pose`、平滑`pose`、decision、saved、photos、age_ms、runtime_provider和分阶段耗时。`device`响应主要字段为：`device_bbox`、设备分数、`contact_point`、可见性、`face_regions`、`contact_region`、模型谱系和运行时信息。坐标均基于未镜像原图。

仓内 `pc_demo/vendor/target_detection/service.py` 还保留纯目标检测接口 `GET /health`、`POST /v1/infer/image`、`POST /v1/stream/frame`、`POST /v1/stream/reset`，但完整联调页面使用根服务，不应同时启动两个入口后混淆端口和状态。

## 8. 从零部署（Windows + WSL2 Ubuntu 22.04）

### 8.1 前置条件

- Windows 10/11、WSL2 Ubuntu 22.04 x86_64。
- Python严格为3.10系列；锁文件解析目标为Linux x86_64。
- Windows Edge或Chrome负责摄像头权限；不需要把USB摄像头透传到WSL。
- 首次安装需要访问Python包索引；模型均已在本目录，无需重新下载。
- CPU路线用于先排通；CUDA路线要求Windows NVIDIA驱动、WSL `nvidia-smi` 可用。

安装uv（已有则跳过）：

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
exec "$SHELL" -l
uv --version
```

进入本目录后先校验，不需要安装第三方包：

```bash
python3 scripts/verify_submission.py
uv lock --check
```

CPU安装与运行：

```bash
bash setup_uv.sh cpu
LAB_RUNTIME_GROUP=cpu bash start_uv.sh
```

CUDA安装与运行：

```bash
nvidia-smi
bash setup_uv.sh cuda
LAB_RUNTIME_GROUP=cuda bash start_uv.sh
```

`pyproject.toml`把公共依赖与 `cpu`/`cuda` 两个ONNX Runtime组分开。默认组是CPU。任何时候都不要同时同步两个组；CUDA必须由 `--no-default-groups --group cuda` 选择，脚本已经执行该约束。`uv.lock`由uv 0.11.27实际解析50个包生成，不是手写文件。

服务默认绑定 `127.0.0.1:8876`。在Windows浏览器打开 `http://127.0.0.1:8876/`。用Ctrl+C停止；程序没有安装系统服务、开机启动或后台守护进程。

### 8.2 环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `LAB_RUNTIME_GROUP` | `cpu` | `start_uv.sh`选择 `cpu` 或 `cuda` 依赖组 |
| `LAB_PORT` | `8876` | HTTP端口，合法范围1–65535 |

主业务代码、模型和阈值都从本目录相对路径读取。运行时只会在本目录生成 `pc_demo/captures/`，以及uv环境/缓存；这些不是业务依赖。若检查发现业务代码读取交付目录之外的固定路径，应视为阻断。

### 8.3 页面操作

1. 打开页面，允许摄像头。
2. 人脸拍照模式先正面单人锁定，再设置目标角度、容差、Pitch/Roll上限和稳定时间。
3. 缓慢转头并在目标附近停留；拒拍原因会显示在进度区。
4. 左右照片保存后可下载或单侧重拍。数字每秒刷新，推理仍逐帧。
5. 切换旧仪器模式后，查看设备框、接触点、七区和接触区域。
6. “显示镜像”只影响画面显示，不修改返回坐标或保存原图。

## 10. 错误处理与排查

| 现象 | 判定与处理 |
|---|---|
| 完整性失败 | 停止运行，按报错路径重新复制；禁止修改清单掩盖哈希变化 |
| `uv lock --check`失败 | pyproject或锁文件被改；重新评审依赖后由uv生成，禁止手工补锁 |
| 网页打不开 | 先看服务终端，再访问 `/health`，核对端口和HTTP协议 |
| 摄像头无画面 | 使用Windows浏览器、授权摄像头、关闭占用摄像头的软件 |
| CUDA未启用 | 以 `/health`实际provider为准，核对WSL驱动、ORT、CUDA和cuDNN |
| 始终不拍照 | 逐项检查Yaw、Pitch、Roll、清晰度、脸尺寸、帧年龄、稳定时间和失锁提示 |
| CPU时进度反复清零 | 单帧可能超过350ms连续门限；先记录耗时，不要无记录删除门禁 |
| 接触点突然消失 | 检查设备框、可见性和结果新鲜度；无有效设备时清空是正确行为 |
| 多个页面互相失效 | 当前只有一个活动session，关闭多余页面后重新开始一轮 |

## 11. RK3568、RK3576与硬件边界

`rk3568_reference/`保留历史C++14服务、RKNN转换、对拍、部署和诊断工具。历史板卡为ATK-DLRK3568，Runtime 1.5.2、driver 0.9.2；曾以ADB转发电脑JPEG到板卡NPU。历史混合量化组合通过既定精度门，但30分钟长稳测试中止，板载 `/dev/video0` STREAMON失败。

本目录只携带RK3568参考源码、原始opset12 ONNX和对拍报告；没有把RKNN二进制、SDK、运行库或ARM64最终二进制伪装成RK3576资产。

RK3576仍需硬件维护人员完成：

1. 确认准确板型、Linux/openvela版本、RKNN Toolkit/Runtime/driver和NPU核心配置。
2. 用匹配RK3576工具链重新转换五个模型；不能直接把RK3568文件改名。
3. 对齐EXIF、BGR/RGB、letterbox、ROI、量化参数、YOLOX三头解码、接触点与角度后处理。
4. 接入实际摄像头和云台协议；本PC程序没有串口/PWM/云台控制实现。
5. 完成模型逐项对拍、100帧性能、30分钟长稳、内存、断连恢复和端到端网页验收。
6. 提供实板 `/health`、NPU provider、模型SHA、系统/驱动版本、日志和演示证据。

普通WSL运行只能证明PC软件和接口，不能替代RK3576 NPU、摄像头、云台或openvela能力调用验收。

## 12. 已知限制

- 设备模型只针对旧仪器；外观差异大的新仪器需重新采集、审查、训练和评估。
- 当前只有左右自动拍照，没有正面槽位；不能直接声称已完成三视图自动采集。
- face/device模式互斥，未做同帧并行性能设计。
- 角度模型存在个体、眼镜、遮挡、相机高度和大侧脸偏差；滤波只抑制跳变，不修复系统误差。
- 空间锁定不是身份识别；页面不适合无人值守多用户并发。
- 视觉接触点不是压力、深度或真实接触传感器。
- 七区不是医学治疗安全区；没有皮肤状态、剂量或注射建议。
- Windows原生Python未验收；推荐Windows浏览器+WSL2 Ubuntu 22.04。
- RK3576、openvela和真实云台没有本地完成证据。
